1. Demonstrate the Three Fundamental Concepts of OOP in Java

1.1 Encapsulation

Encapsulation is the concept of wrapping data (variables) and methods into a single unit called a class. It restricts direct access to some of an object's components and provides controlled access through getter and setter methods

Encapsulation: The fields name and age are private and can only be accessed via getter and setter methods.

1.2 Polymorphism

Polymorphism means "many shapes" and allows a method or class to take many forms. It can be achieved through method overriding (runtime polymorphism) and method overloading (compile-time polymorphism).

Polymorphism: The sound() method is overridden in both Dog and Cat classes. The actual method called depends on the type of the object being referred to, not the reference type.

1.3 Inheritance

Inheritance allows one class (child) to inherit the properties and methods of another class (parent).

Inheritance: Dog extends Animal, so it inherits the eat() method from the Animal class and can also define its own methods like bark().

2. Wrapper Classes in Java

In Java, primitive data types (like int, double, etc.) are not objects. However, wrapper classes allow these primitive types to be treated as objects. For example, Integer is the wrapper class for the primitive int, and Double is the wrapper class for double. Why do we need wrapper classes?
Autoboxing and Unboxing: Java allows automatic conversion between primitives and their corresponding wrapper classes. For example, an int can be automatically converted to an Integer and vice versa.
Collection Framework: Wrapper classes are used in data structures like ArrayList and HashMap, which can only store objects, not primitives.
Utility methods: Wrapper classes provide useful methods, like converting between strings and numbers (Integer.parseInt()).

3. Difference Between HashMap and Hashtable

Thread Safety: HashMap is not synchronized, meaning it's not thread-safe.
Hashtable is synchronized, making it thread-safe.
Null Keys and Values: HashMap allows one null key and multiple null values. Hashtable does not allow null keys or values.
Performance: HashMap generally performs better because it doesn't need synchronization overhead.

4. String Pool in Java

String Pool is a special storage area in memory where Java stores string literals to optimize memory usage. When you create a string literal, Java checks if that string already exists in the pool. If it does, it reuses the existing object; otherwise, it creates a new one.
String Immunity refers to the fact that once a string is created in the string pool, it cannot be modified, ensuring immutability of strings.

5. Garbage Collection in Java

Garbage Collection is the automatic process of reclaiming memory in Java by removing objects that are no longer in use or reachable. The JVM uses a garbage collector to clean up unused objects.

  • Minor GC: Clears the Young Generation.
  • Major GC (Full GC): Clears both Young and Old Generations.
    • G1 Garbage Collector: Aims to achieve predictable pause times while cleaning up large heaps.
  • CMS Garbage Collector: Minimizes pause times by performing concurrent collection.

6. Access Modifiers in Java

Access modifiers in Java specify the visibility or accessibility of classes, methods, and variables. The four types are:

  • Public: Accessible from anywhere.
  • Private: Accessible only within the same class.
  • Protected: Accessible within the same package or by subclasses.
  • Default (Package-Private): Accessible only within the same package.

7. final Keyword in Java

The final keyword can be used with variables, methods, and classes:

  • Final Variable: The value cannot be changed after initialization.
  • Final Method: The method cannot be overridden.
  • Final Class: The class cannot be subclassed.

8. static Keyword in Java

  • Static Variable: Belongs to the class, not to instances. It is shared among all instances.
  • Static Method: Can be called without creating an instance of the class.
  • Static Block: Used for static initialization.

9. Differences Between Overriding and Overloading

  • Overloading: Defining multiple methods with the same name but different parameter types or number of parameters.
  • Static Method: Can be called without creating an instance of the class.
  • Overriding: A subclass provides its own implementation of a method defined in the superclass.

10. Method Signature and Overloading/Overriding

In Java, the method signature consists of the method's name and the parameter types. It helps distinguish between overloaded methods.

  • Overloading occurs when methods have the same name but different signatures.
  • Static Method: Can be called without creating an instance of the class.
  • Overriding occurs when a subclass provides a new implementation for a method defined in its superclass with the same signature.

11. super and this

  • super: Refers to the superclass. It can be used to access superclass methods and constructors.
  • this: Refers to the current object.

12. How equals() and hashCode() Work in Java

In Java, equals() and hashCode() are two fundamental methods that determine how objects are compared and how they behave in hash-based collections like HashMap, HashSet, and Hashtable.

  • equals():
    The equals() method is used to compare two objects for logical equality. By default, the equals() method in the Object class compares the memory addresses of objects (reference comparison). However, you can override this method to provide a custom definition of equality based on the object's fields. Overriding equals():
    To implement equality properly, you should override the equals() method to compare the actual contents of two objects.
  • hashCode():
    The hashCode() method returns an integer that represents the hash value of the object. The hash code is primarily used in hash-based collections (like HashMap, HashSet, and Hashtable) to efficiently store and retrieve objects. Why is hashCode() important?
    If two objects are considered equal (as determined by equals()), they must return the same hash code.
    If two objects have different hash codes, they are considered unequal, and equals() doesn't need to be called.

Important Guidelines:
Consistency: If two objects are equal, they must return the same hash code consistently throughout the lifetime of the objects.
Contract between equals() and hashCode(): If equals() returns true, then hashCode() must return the same value. If equals() returns false, hashCode() can return different values, but it’s not mandatory.

13. Java Load Sequence

When a Java application is run, several steps occur in a specific sequence to load and execute the program.

Java Class Loading Process:

  1. Class Loading: The class loader loads classes into memory when they are first referenced. The class loader checks if the class is already loaded; if not, it loads the class file from the disk (or other locations such as network or cache).
  2. Static Initialization: The static block in a class (if present) is executed only once when the class is first loaded into memory.
    Static variables are initialized at this stage.
  3. Constructor Call: After static initialization, the instance constructor is called when an object is created. Constructors initialize instance variables and execute any setup code.
  4. Method Execution: The main method (or other entry points) is executed after the class has been loaded and the constructors have been invoked.

Class Loading Details:

  • Bootstrap Class Loader: Loads core Java libraries from the JDK.
  • Extension Class Loader: Loads classes from the ext directory.
  • System/Application Class Loader: Loads classes from the classpath.

14. What is Polymorphism? How Does Java Implement It?

Polymorphism is one of the four fundamental principles of Object-Oriented Programming (OOP). It allows objects of different types to be treated as objects of a common superclass. There are two types of polymorphism in Java:

  1. Compile-time Polymorphism (Method Overloading): Occurs when multiple methods with the same name exist in the same class, but with different parameter types or number of parameters.
    Method Overloading is resolved at compile time.
  2. Runtime Polymorphism (Method Overriding): Occurs when a subclass provides a specific implementation of a method defined in the superclass.
    Method Overriding is resolved at runtime, meaning the JVM decides which version of the method to invoke at runtime, depending on the object type.

15. What is Encapsulation? How Does Java Implement It? Why Do We Need Encapsulation?

Encapsulation is the mechanism of bundling the data (fields) and the methods that operate on the data into a single unit, usually a class, and restricting access to some of the object's components.

    How Java Implements Encapsulation:
  • Private Fields: Fields are made private to restrict direct access from outside the class.
  • Public Getter and Setter Methods: Public methods provide controlled access to the private fields, allowing data to be accessed or modified in a controlled manner.
    Why Do We Need Encapsulation?
  • Data Protection: By making fields private, you can ensure that data is protected and only modified in a controlled manner.
  • Maintainability: Encapsulation provides the flexibility to change the internal implementation without affecting the external code that uses the class.
  • Flexibility: You can add validation or additional logic inside getter or setter methods to control how data is accessed or modified.

16. Compare Interface and Abstract Class with Use Cases

Both interfaces and abstract classes are used in Java to represent abstract types, but they have different use cases and capabilities.

Comparison: Interface vs Abstract Class

Feature Interface Abstract Class
Methods Can only have abstract methods (before Java 8), but from Java 8 onward, can have default and static methods. Can have both abstract and concrete (non-abstract) methods.
Multiple Inheritance A class can implement multiple interfaces. A class can inherit from only one abstract class.
Constructors Cannot have constructors. Can have constructors.
Fields All fields are implicitly public, static, and final. Can have any type of fields, including instance fields.
Use Case Used when different classes from different hierarchies need to implement the same set of methods. Used when classes share some common functionality but also have some differing functionality.
Use Cases:
  • Interface: When you need to define a contract that multiple classes should adhere to, regardless of the class hierarchy. Interface is used for defining a contract for different types of classes, providing a common set of behaviors without enforcing a class hierarchy.
  • Abstract Class: When you want to provide some common functionality while leaving other methods for subclasses to implement. Abstract Class allows partial implementation with some methods having default behavior, suitable for shared functionality across related classes.
