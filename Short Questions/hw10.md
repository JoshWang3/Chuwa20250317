## 2. Explain tight coupling vs loose coupling and what does Spring IOC do?
### Tight Coupling
- One class creates or depends direcly on another class
- Makes it hard to change, test, or reuse
- Example:
```java
class Car {
  Engine engine = new Engine(); 
}
```
if wanna to change engine
```java
engine = new ElectricEngine(); // must edit Car class itself
```
when test, cannot use fake engine to mock
```java
Car car = new Car(); // always uses real Engine
```

### Loose Coupling
- One class relies on an interface or abstraction class
- Makes it flesible, testable, and resuable.
- Example:
```java
class Car {
    Engine engine;
    Car(Engine engine) { this.engine = engine; }
}
```
easy to change if we wanna a different engine
```java
Car car = new Car(new ElectricEngine()); // no need to edit Car class
```
can pass in a fake engine for testing:
```java
class FakeEngine implements Engine {
    public void start() {
        System.out.println("Fake start for test!");
    }
}

Car car = new Car(new FakeEngine());
```

### What does Spring IoC do?
Inversion of control, unlike common Java code, engineer creates and controls objects by `new`. Spring creates and injects beans(objects) automatically. Helps us build loopse coupling system.
```java
// Without Spring
Engine engine = new ElectricEngine();
Car car = new Car(engine);
```
```java
// With Spring
@Component
class Engine {}

@Component
class Car {
  private final Engine engine;
  @Autowired
  public Car(Engine engine) {
    this.engine = engine;
  }
}
```
In this way:
- beans are loose coupling
- easy to switch implementations like `@Primary`, `@Qualifier`, etc
- easy to test, Spring can inject mock beans

## 3. What is MVC pattern?
MVC stands for Model-View-Controller. It's a design pattern that helps us organize code in web applications by separating business logic, UI, and user input.

### Components
- Model: Holds the data and business logic. In Spring, Java classes like User, Post are models.
- View: Displays data to the user (UI). In Spring, HTML, JSP are views.
- Controller: Handles user input, updates the model, and selects the view. In Spring, a class with `@Controller` that maps requests like `/users` is a controller, it handels the http request.

### Flow of MVC
1. In the view, the user clicks a button or sends a request → goes to the controller.
2. The controller talks to the model; the model gets or updates data.
3. The model sends data back.
4. The controller gives data to the view.
5. The view renders the result as a webpage.

## 4. What is Front-Controller?
A Front-Controller is a single entry point for handling all incoming client requests in a web application.
In Spring, the Front-Controller is the `DispatcherServlet`
- Intercepts all incoming HTTP requests
- Decides which controller should handle the request
  - example: url `/users`, http method GET -> `DispatcherServlet` checks all controllers and decide to go to `UserController.getUsers()`
- Delegates to the right controller method
  - It calls the controller method
    ```java
    @GetMapping("/users")
    public String getUsers(Model model) {
        ...
    }
    ```
- Receives the result (model + view or data)
  - The controller returns something (like a view name or data), and DispatcherServlet receives it to prepare the response.
- Renders the response (e.g., web page or JSON)
  - If the return is a view name, Spring renders the corresponding HTML/JSP with model data.
  - If it's data (like in @RestController), Spring converts it to JSON and sends it back to the client.

### `DispatcherServlet` work flow
1. Client sends request (e.g. GET /users)
2. DispatcherServlet receives it (acts as the Front-Controller)
   - Finds the correct controller
   - Matches URL + HTTP method → calls controller method
3. Controller processes the request
   - May call service/model, prepares data
   - Controller returns a view name + model data, or just data (JSON)
4. DispatcherServlet handles the result
   - If view name → passes to ViewResolver
   - If data → uses HttpMessageConverter
   - Renders response
     - View becomes HTML
     - data becomes JSON
5. Response sent to client

## 6. What is JSP and What is Model And View？
### JSP
- JSP stands for JavaServer Pages
- It’s a view technology used to build dynamic web pages in Java web apps.
- It allows mixing HTML + Java code to display content based on backend data.
```jsp
<h1>Hello, ${name}</h1>
```
This will show Hello, Elena if the backend sets name = "Elena" in the model.

### What is Model and View?
In Spring MVC, the controller returns both 
- Model: the data to display
- View: the name of the page to render(eg. userList.jsp)
- Spring uses `ModelAndView` to wrap both together
```java
return new ModelAndView("userList", "users", users);
// "userList" → tells Spring to use userList.jsp (the view)
// "users" → is the key for the data in the model
```

## 7. Explain servlet and servlet container, name some servlet implementations and servlet containers other than tomcat
### Servlet
- A Servlet is a Java class that handles HTTP requests and responses.
- It runs on the server and builds dynamic web content (like HTML, JSON).
- Write it by extending HttpServlet and overriding methods like doGet() or doPost().
```java
public class HelloServlet extends HttpServlet {
    protected void doGet(HttpServletRequest req, HttpServletResponse resp) {
        resp.getWriter().write("Hello from Servlet!");
    }
}
```
### Servlet Container
A Servlet Container is part of a web server that:
- Loads and runs servlet classes
- Manages servlet lifecycle (init → service → destroy)
- Handles HTTP requests and forwards them to the correct servlet

### Servlet Implementations
Actual Java classes that implement the servlet API:
- `GenericServlet`
- `HttpServlet`

### Difference between Servlet and `dispatcherServlet`
Servlet
- servlet is a basic Java class that handles HTTP requests and responses.
- We can write it by ourselves via implementing `GenericServlet` or extending `HttpServlet`
`dispatcherServlet`
- `dispatcherServlet` is a Spring-specific servlet that implements the Front-Controller pattern. It’s provided by Spring — we don’t write it ourselves. It handles routing, calling controllers, passing model data, and rendering views or JSON.

### Servlet and API
- A Servlet is an implementation (Java class) that uses the Servlet API.
- The Servlet API is a set of Java interfaces (like HttpServlet, ServletRequest) that define how web servers should handle HTTP requests.
