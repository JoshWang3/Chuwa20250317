2. Explain `tight coupling` vs. `loose coupling`. What does Spring IoC do?

   **Tight Coupling:** 

   When classes and objects are highly dependent on each other. In tight coupling, a class assumes too many details about another class or directly creates instances of dependent classes.

   ```java
   public class OrderService {
       // Tight coupling - direct instantiation
       private PaymentProcessor paymentProcessor = new CreditCardProcessor();
       
       public void processOrder(Order order) {
           // Using tightly coupled dependency
           paymentProcessor.processPayment(order.getAmount());
       }
   }
   ```

   **Loose Coupling:** 

   When classes and objects have minimal knowledge about each other. Components interact through abstractions (interfaces or abstract classes) rather than concrete implementations.

   ```java
   public class OrderService {
       // Loose coupling - depends on abstraction
       private PaymentProcessor paymentProcessor;
       
       // Dependency is provided from outside
       public OrderService(PaymentProcessor paymentProcessor) {
           this.paymentProcessor = paymentProcessor;
       }
       
       public void processOrder(Order order) {
           paymentProcessor.processPayment(order.getAmount());
       }
   }
   
   // Interface that different implementations can follow
   public interface PaymentProcessor {
       void processPayment(double amount);
   }
   ```

   **Spring IoC (Inversion of Control)**

   Spring IoC is a core principle that addresses the problem of tight coupling by:

   1. **Inversion of Control:** Shifts the responsibility of managing object creation and dependencies from the application code to the Spring container.
   2. **Dependency Injection:** Spring container injects the required dependencies into objects rather than the objects creating their dependencies themselves.

   **Benefits of Spring IoC**:

   - Reduced dependencies between components

   - Easier unit testing through mocking

   - Greater flexibility to switch implementations

   - Simplified application configuration

   - Promotes programming to interfaces

     

3. What is MVC pattern?

   MVC (Model-View-Controller) is an architectural design pattern that separates an application into three main logical components:

   1. **Model**: Represents the application data and business logic
      - Contains the core functionality and data
      - Maintains the data integrity
      - Independent of the user interface
   2. **View**: Displays the data to the user
      - Presents the model's data to the user
      - Receives user input
      - Never directly communicates with the model
   3. **Controller**: Acts as an intermediary between Model and View
      - Processes incoming requests
      - Handles user input
      - Manipulates model data
      - Selects the appropriate view to render

   **Benefits of MVC Pattern**

   - **Separation of Concerns**: Each component has a specific responsibility

   - **Code Reusability**: Model and controller components can be reused across different views

   - **Parallel Development**: Different team members can work on models, views, and controllers simultaneously

   - **Easier Maintenance**: Changes to one component have minimal impact on others

   - **Better Testability**: Each component can be tested independently

     

4. What is the Front Controller?

   The Front Controller is a design pattern in web application architecture that provides a centralized entry point for handling all requests to the application. It acts as the first point of contact for incoming HTTP requests and manages the request processing workflow.

   Key characteristics of the Front Controller pattern:

   1. **Centralized Control**: All requests pass through a single controller before being dispatched to appropriate handlers
   2. **Request Preprocessing**: Performs common operations like authentication, logging, and request filtering
   3. **Request Dispatching**: Routes requests to the appropriate handlers based on the request type or URL
   4. **Response Coordination**: Manages the view selection and response generation

   **How the DispatcherServlet Works**

   1. Receives HTTP request

   2. Consults `HandlerMapping` to find the appropriate controller

   3. Invokes the selected controller to process the request

   4. Gets the `ModelAndView` returned by the controller

   5. Resolves the view name to an actual view implementation

   6. Renders the view with the model data

   7. Returns the response to the client

      

5. Explain DispatcherServlet and how it works.

   DispatcherServlet is the front controller in Spring MVC applications. It is a central servlet that coordinates the entire request processing workflow. As the heart of Spring MVC, it implements the Front Controller design pattern and handles all the HTTP requests and responses.

   The workflow of DispatcherServlet follows these steps:

   1. **Request Reception**:

      ```java
      // Web request arrives at the DispatcherServlet
      public class DispatcherServlet extends FrameworkServlet {
          @Override
          protected void doService(HttpServletRequest request, HttpServletResponse response) {
              // Process incoming request
          }
      }
      ```

   2. **Handler Mapping**:

      - Determines which Controller should handle the request based on URL pattern
      - Uses configured HandlerMapping beans to find the appropriate handler

      ```java
      HandlerExecutionChain mappedHandler = getHandler(request);
      ```

   3. **Handler Adapter Resolution**:

      - Finds the appropriate HandlerAdapter that can execute the selected handler

      ```java
      HandlerAdapter ha = getHandlerAdapter(mappedHandler.getHandler());
      ```
   
   4. **Handler Execution**:

      - The adapter invokes the handler method in the controller
      - Controller processes the request and returns a ModelAndView object
   
      ```java
      ModelAndView mv = ha.handle(request, response, mappedHandler.getHandler());
      ```
   
   5. **View Resolution**:

      - ViewResolver translates the logical view name to an actual View implementation

      ```java
      View view = viewResolver.resolveViewName(mv.getViewName(), locale);
      ```
   
   6. **View Rendering**:

      - The View renders the response using the model data

      ```java
      view.render(mv.getModel(), request, response);
      ```
   
   **Key Components That Work with DispatcherServlet**

   1. **HandlerMapping**: Maps requests to handlers

   2. **HandlerAdapter**: Executes handlers

   3. **ViewResolver**: Resolves view names to View implementations

   4. **LocaleResolver**: Resolves the locale for internationalization

   5. **ThemeResolver**: Resolves themes for UI

   6. **HandlerExceptionResolver**: Handles exceptions during processing

      

6. What is JSP, and what is Model and View？

   JSP (JavaServer Pages) is a technology used for creating dynamic web content with Java. It allows developers to embed Java code directly into HTML pages using special tags.

   Key features of JSP include:

   1. **Server-side processing**: JSP pages are processed on the server before being sent to the client
   2. **Java integration**: Allows embedding Java code within HTML
   3. **Tag libraries**: Provides custom tags for common functionality
   4. **Expression Language (EL)**: Simplifies access to Java objects

   In the MVC (Model-View-Controller) pattern, "Model and View" refers to two key components:

   **Model**

   The Model represents the application's data and business logic:

   - Contains the core functionality of the application
   - Manages the data, logic, and rules of the application
   - Notifies observers (usually views) when data changes
   - Is independent of the user interface

   Examples of Model components in Spring:

   - Java beans/POJOs
   - Service classes
   - Repository classes

   **View**

   The View is responsible for presenting data to the user:

   - Renders the model data
   - Sends user actions to the controller
   - Allows for multiple visual representations of the same data
   - Should be passive and not contain business logic

   Examples of View components in Spring:

   - JSP pages
   - Thymeleaf templates
   - HTML pages
   - JSON/XML responses (for RESTful services)

7. Explain servlet and servlet container. Name some servlet implementations and servlet containers other than Tomcat.

   A **servlet** is a Java programming language class that extends the capabilities of servers that host applications accessed by means of a request-response programming model. Servlets are used to handle requests and generate dynamic responses in web applications.

   Key characteristics of servlets:

   - Java classes that implement the `javax.servlet.Servlet` interface
   - Handle HTTP requests and generate responses
   - Maintain state between requests using the session mechanism
   - Support lifecycle methods (init, service, destroy)

   A **servlet container** (also known as a web container) is a component of a web server that interacts with servlets. It manages the lifecycle of servlets, maps a URL to a particular servlet, and ensures that the URL requester has the correct access rights.

   Responsibilities of a servlet container:

   - Managing servlet lifecycle
   - Creating request and response objects
   - Handling multiple requests concurrently
   - Managing sessions
   - Providing security mechanisms
   - Supporting servlet configuration

   **Servlet Implementations**

   1. **HttpServlet**: Most common implementation for handling HTTP requests
   2. **GenericServlet**: Base class for all servlets, protocol-independent
   3. **FacesServlet**: Core of JavaServer Faces (JSF) technology
   4. **DispatcherServlet**: Front controller in Spring MVC
   5. **Jersey's ServletContainer**: For RESTful web services

   **Servlet Containers Other Than Tomcat**

   1. Jetty
      - Lightweight and flexible
      - Easily embeddable in applications
      - Used in projects like Spark, Hadoop, and Solr
   2. Undertow
      - High-performance web server
      - Core component of WildFly (formerly JBoss)
      - Non-blocking architecture
   3. GlassFish
      - Reference implementation for Java EE
      - Provides full application server capabilities
      - Supports clustering and high availability
   4. WebLogic Server
      - Commercial offering from Oracle
      - Enterprise-grade features for large-scale applications
      - Strong support for mission-critical systems
   5. WebSphere Application Server
      - IBM's Java application server
      - Focuses on reliability and scalability
      - Available in various editions for different needs
   6. Resin
      - Fast servlet container from Caucho Technology
      - Known for its performance optimizations
      - Supports both open-source and professional editions
