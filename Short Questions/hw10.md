2. Explain tight coupling vs loose coupling and what does Spring IOC do?
* **Tight Coupling**:

  * Components are **highly dependent** on each other.
  * One change in a class **requires changes in dependent classes**.
  * Example: A `Car` class directly creates an instance of `Engine` class.

    ```java
    class Car {
        Engine engine = new Engine(); // tightly coupled
    }
    ```

* **Loose Coupling**:

  * Components are **independent and communicate via interfaces or abstractions**.
  * Easier to modify, test, and maintain.
  * Achieved via **Dependency Injection (DI)**.

* **What Spring IoC Does**:

  * **Inversion of Control (IoC)** means **the control of creating objects is given to Spring**.
  * Spring manages dependencies via **Dependency Injection**, promoting **loose coupling**.
  * Example using Spring:

    ```java
    @Component
    class Engine { }

    @Component
    class Car {
        private final Engine engine;
        public Car(Engine engine) {
            this.engine = engine;
        }
    }
    ```
    
3. What is MVC pattern?
* **MVC (Model-View-Controller)** is a design pattern to **separate concerns** in an application:

  * **Model**: Represents business logic/data (e.g., Java classes, database entities).
  * **View**: User interface (e.g., HTML, JSP).
  * **Controller**: Handles user input and routes it to model or view.
  
4. What is Front-Controller? 
* A **Front Controller** is a **single entry point** for handling all requests.
* It **centralizes request handling**.
* In Spring MVC, the **`DispatcherServlet`** is the front controller.


5. Explain DispatcherServlet and how it works.
* `DispatcherServlet` is the **core component of Spring MVC**.
* Acts as the **front controller**.
* Workflow:

  1. Client sends HTTP request to the server.
  2. `DispatcherServlet` receives the request.
  3. It consults the **HandlerMapping** to find a suitable **Controller**.
  4. The Controller processes the request and returns a **ModelAndView**.
  5. `DispatcherServlet` sends this to **ViewResolver**.
  6. The view is rendered (e.g., a JSP) and returned to the client.


6. What is JSP and What is Model And View？
* **JSP (JavaServer Pages)**:

  * A Java-based technology to create **dynamic web pages**.
  * Allows embedding Java code in HTML using tags like `<% %>`.
  * Often used as **view technology** in MVC.

* **ModelAndView**:

  * A Spring class that holds both:

    * **Model**: Data to be rendered.
    * **View**: Name of the view (like JSP page).
  * Example:

    ```java
    @GetMapping("/hello")
    public ModelAndView sayHello() {
        ModelAndView mv = new ModelAndView("hello");
        mv.addObject("message", "Hello Spring!");
        return mv;
    }
    ```
    
7. Explain servlet and servlet container , name some servlet implementations and servlet containers 
other than tomcat. 
* **Servlet**:

  * A Java class used to handle HTTP requests and responses.
  * It runs inside a **servlet container**.
  * Lifecycle methods: `init()`, `service()`, `destroy()`.

* **Servlet Container**:

  * Manages lifecycle, threading, and request-response handling of servlets.
  * Examples:

    * **Apache Tomcat** (most common)
    * **Jetty**
    * **Undertow**
    * **Resin**
    * **GlassFish** (full Java EE server)
