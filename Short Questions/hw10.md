## 2. Tight Coupling vs Loose Coupling

### Tight Coupling

- In tightly coupled code, classes are highly dependent on each other.
- Changing one class often requires changes in other classes.
- Makes testing and maintenance harder.

#### Example (Tightly Coupled):
```java
public class Car {
    private Engine engine = new Engine(); // directly creating the dependency

    public void start() {
        engine.run();
    }
}
```

### Loose Coupling
- In loosely coupled code, classes rely on abstractions (interfaces), not concrete implementations.

- Easier to modify, test, and scale.

```java
public interface Engine {
    void run();
}

public class PetrolEngine implements Engine {
    public void run() {
        System.out.println("Petrol engine running...");
    }
}

public class Car {
    private Engine engine;

    public Car(Engine engine) { // dependency injected via constructor
        this.engine = engine;
    }

    public void start() {
        engine.run();
    }
}
```

### Spring IoC
Inversion of Control (IoC) is a principle where the control of object creation and dependency management is transferred from the application code to the Spring container.

- Spring manages the lifecycle and injection of dependencies (beans).

- Promotes loose coupling by injecting dependencies at runtime.

- Uses annotations like @Component, @Autowired, @Configuration, etc.

## 3. MVC Pattern

### MVC stands for Model-View-Controller

It is a design pattern used in web applications to separate concerns, making the code more modular and maintainable.

### Model

- Represents the **data** and business logic.
- Responsible for interacting with the database and performing operations.
- Example: Java classes like `User`, `Product`, `Order`, etc.

### View
- Represents the UI layer that the user interacts with.

- In Spring MVC, this is usually implemented using JSP, Thymeleaf, or HTML templates.

### Controller
- Acts as the intermediary between Model and View.

- Handles HTTP requests, processes input, and returns the response.

### How it Works in Spring MVC
- User sends a request (e.g., /user) → handled by the Controller.

- The Controller prepares the Model data.

- The View uses this data to generate the HTML response.

- Response is sent back to the user’s browser.

---

## 4.  Front Controller

### Definition

The Front Controller is a design pattern where a single handler (controller) handles all the incoming requests to a web application.

In Spring MVC, the `DispatcherServlet` acts as the Front Controller.


### Purpose

- Centralizes request handling logic.
- Routes the request to the appropriate **Controller**, **View**, or **Handler**.
- Provides common behaviors like logging, authentication, and error handling.

---

## 5. DispatcherServlet

### Definition
- `DispatcherServlet` is the **core component** of Spring MVC.
- It acts as the **Front Controller** of the Spring MVC framework.
- It intercepts **all incoming HTTP requests** and dispatches them to the appropriate handler/controller.

### DispatcherServlet Workflow

```text
Client Request
      ↓
DispatcherServlet
      ↓
HandlerMapping → Controller → Business Logic
      ↓
ViewResolver
      ↓
Response to Client
```

## 6. JSP, Model And View

###  JSP

- JSP is a **view technology** used to render dynamic HTML content.
- Allows embedding **Java code inside HTML** using special JSP tags (`<% %>`, `${}`).
- In Spring MVC, JSP is often used as the **view layer** to display data sent from controllers.

### Model
- Represents the data sent from the controller to the view.

- Usually populated using the Model or ModelAndView object.

### View
- Responsible for rendering the output (HTML, JSP, Thymeleaf, etc.)

- In Spring, the view name returned by the controller is resolved by a ViewResolver to a JSP file or other UI template.


## Servlet, Servlet Container

### Servlet

- A **Servlet** is a Java class used to handle HTTP requests and generate responses.
- It runs on the **server-side** inside a **servlet container**.
- Part of Java EE specification.

## Servlet Container?
- A Servlet Container (or Servlet Engine) is part of a web server that interacts with servlets.

It:

- Manages servlet lifecycle

- Maps URLs to servlets

- Handles requests and responses

- Provides multithreading, security, and session management
