## 3. Compare `let` vs `var`

| Feature                  | `var`                         | `let`                          |
|--------------------------|-------------------------------|--------------------------------|
| Scope                   | Function-scoped               | Block-scoped                  |
| Hoisting                | Yes (initialized as `undefined`) | Yes (but not accessible before declaration - TDZ) |
| Redeclaration           | Allowed                       | Not allowed in same scope     |
| Reassignment            | Allowed                       | Allowed                        |

### Scope Difference

```javascript
function testVarLetScope() {
    if (true) {
        var x = 10;
        let y = 20;
    }
    console.log(x); // 10 (function scope)
    console.log(y); // ReferenceError: y is not defined (block scope)
}
testVarLetScope();
```

### Example 2: Hoisting Behavior

```javascript
console.log(a); // undefined (hoisted var)
var a = 5;

console.log(b); // ReferenceError: Cannot access 'b' before initialization
let b = 10;
```
### Example 3: Redeclaration

```javascript
var x = 1;
var x = 2; // OK

let y = 1;
let y = 2; // SyntaxError: Identifier 'y' has already been declared
```

## 4. Closures


A **closure** is a function that **"remembers" its outer variables** even after the outer function has returned.

Closures allow functions to have **private variables**, preserve state, and access outer scopes even after they finish execution.

### Example

```javascript
function outer() {
    let counter = 0;

    function inner() {
        counter++;
        console.log(counter);
    }

    return inner;
}

const count = outer();
count(); // 1
count(); // 2
count(); // 3
```

## 5. Callback Hell

**Callback Hell** (also known as the "Pyramid of Doom") happens when multiple asynchronous operations are nested within each other using callbacks.  

### Example

```javascript
function step1(callback) {
    setTimeout(() => {
        console.log("Step 1 complete");
        callback();
    }, 1000);
}

function step2(callback) {
    setTimeout(() => {
        console.log("Step 2 complete");
        callback();
    }, 1000);
}

function step3(callback) {
    setTimeout(() => {
        console.log("Step 3 complete");
        callback();
    }, 1000);
}

// Nested callbacks (callback hell)
step1(() => {
    step2(() => {
        step3(() => {
            console.log("All steps done");
        });
    });
});
```

## 6. `Promise`, `async`, and `await`

### Promise

A **Promise** is an object representing the eventual **success** or **failure** of an asynchronous operation.

It has 3 states: `pending`, `fulfilled`, or `rejected`.

---

### Example: 

```javascript
function fetchData() {
    return new Promise((resolve, reject) => {
        setTimeout(() => {
            resolve("Data received");
            // reject("Error occurred");
        }, 1000);
    });
}

fetchData()
    .then(data => console.log(data))
    .catch(err => console.error(err));
```

### `async`

- The `async` keyword is used to declare an **asynchronous function**.
- It automatically returns a **Promise**.

### Example

```javascript
async function sayHello() {
    return "Hello!";
}

sayHello().then(msg => console.log(msg)); // "Hello!"
```

### `await`

- `await` is used **inside async functions** to pause execution until the **Promise resolves**.
- It makes asynchronous code look synchronous.

### Example

```javascript
function fetchData() {
    return new Promise((resolve) => {
        setTimeout(() => {
            resolve("Async data loaded");
        }, 1000);
    });
}

async function loadData() {
    console.log("Start...");
    const data = await fetchData(); // Waits here
    console.log(data);
    console.log("Done!");
}

loadData();
```

## 9. How JavaScript Implements Asynchronous Non-Blocking Features


| Concept      | Description                                                                 |
|--------------|-----------------------------------------------------------------------------|
| Call Stack   | Executes synchronous code, one frame at a time                             |
| Event Loop   | Coordinates execution of queued tasks (macrotasks/microtasks)               |
| Macrotask Queue | Holds tasks like `setTimeout`, `setInterval`, I/O callbacks             |
| Microtask Queue | Holds tasks like `Promise.then`, `MutationObserver`, `queueMicrotask`   |


## The Event Loop

1. Executes all synchronous code in the **call stack**
2. Clears the **microtask queue** (Promises, `queueMicrotask`)
3. Then processes **one macrotask** (like `setTimeout`)
4. Repeats the loop

---

### Example: Macrotask vs Microtask

```javascript
console.log("Start");

setTimeout(() => {
    console.log("Macrotask: setTimeout");
}, 0);

Promise.resolve().then(() => {
    console.log("Microtask: Promise.then");
});

console.log("End");
```

### Example: Manual Microtask

```javascript
console.log("Start");

queueMicrotask(() => {
    console.log("Microtask: via queueMicrotask");
});

console.log("End");
```

### Example: Long-Running Task + Event Loop

```javascript
console.log("Start");

setTimeout(() => {
    console.log("Timeout executed");
}, 0);

for (let i = 0; i < 1e9; i++) {} // Simulate heavy blocking work

console.log("End");
```
