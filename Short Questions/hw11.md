6. Explain HTTP Session?
   An HTTP session refers to a series of related interactions between a client (usually a web browser) and a server that are maintained over multiple HTTP requests and responses.
7. Explain Cookie?
   A cookie is a small piece of data that a server sends to the user's browser, which the browser then stores and sends back to the server with future requests to the same domain. Cookies are commonly used for session management, user tracking, and personalization.
8. Compare Session and Cookie?
   Feature	Session	Cookie
   Storage location	Server-side (data stored on the server)	Client-side (data stored in the user's browser)
   Capacity	Large (limited by server memory or storage backend like Redis/DB)	Small (typically ~4KB per cookie)
   Security	More secure (data isn’t exposed to the client)	Less secure (data is stored client-side and can be seen/modified if not protected)
   Speed	May be slower (requires server lookup)	Faster access on the client side
   Lifetime	Usually expires when browser closes or after a timeout	Can persist based on Expires/Max-Age or be session-based
   Storage format	Arbitrary data (e.g., objects)	String key-value pairs only
   Use case	Authentication, user state, shopping cart, etc.	User preferences, tracking IDs, remembering username, etc.
   Modification	Only by server (secure)	Can be modified by client (unless HttpOnly is set)
   Requires cookie?	Yes, usually a cookie stores the session ID on the client	No, cookies are independent (data is in the cookie itself)

10. How do we use session and cookie to keep user information across the the application?
User logs in (e.g., submits login form)
Server verifies credentials and:
Creates a session (on the server) to store user information (e.g., username, user ID)
Sends a cookie to the client’s browser containing the session ID
On each subsequent request:
The browser sends the session ID cookie
The server retrieves the corresponding session data using that session ID
Server uses that session data to determine who the user is and maintain their state
11. What is the spring security filter?
In Spring Security, a filter is a component in the Java Servlet Filter chain that processes incoming HTTP requests and applies security logic (e.g., authentication, authorization, session handling). 
Spring Security uses a series of filters to protect web applications, and these filters execute before your controller logic.

15. What is the disadvantage of Session? how to overcome the disadvantage?
    | Problem                         | Description                                                                                                                                          |
    | ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
    | **1. Server-side memory usage** | Sessions are stored on the server (in memory, database, or distributed cache), which consumes resources and may not scale well for large user bases. |
    | **2. Lack of statelessness**    | HTTP is stateless, but sessions add state. This breaks REST principles and can cause problems in distributed systems or microservices.               |
    | **3. Session stickiness**       | In a load-balanced setup, sessions may tie a user to a specific server ("sticky session"), reducing scalability and fault tolerance.                 |
    | **4. Expiry and cleanup**       | Managing session expiry and cleanup can be complex and lead to stale data or security risks.                                                         |
    | **5. Security risks**           | Session IDs can be hijacked if not transmitted securely (e.g., over HTTP, via XSS/CSRF).                                                             |

17. What is the role of configure(HttpSecurity http) and configure(AuthenticationManagerBuilder auth)?
