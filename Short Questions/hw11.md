2. Explain TLS, PKI, certificate, public key, private key, and signature.
TLS: (Transport Layer Security) the protocol used to secure communication between clients and servers over a network. Encrypts data in transit to prevent snooping. Ensures data integrity and authenticity.
PKI: (Public Key Infrastructure) the framework that manages public and private keys, along with certificates. It includes: Certificate Authorities (CAs) who issue certificates, standards for trust and key and certificate management.
Certificate: A digital certificate binds an identity to a public key. Includes: Owner info (like domain name), public key, expiration date, issuer, digital signature from the CA.
Public Key: Shared openly; used to encrypt or verify a signature.
Private Key: Kept secret; used to decrypt or sign.
Signature: A signature proves the authenticity and integrity of a message or certificate.

6. Explain HTTP Session?

7. Explain Cookie?
A cookie is a small piece of data stored on the client-side (browser) that a server can use to store and retrieve information between HTTP requests. Since HTTP is stateless, cookies help maintain user-related information like login status, preferences, and tracking data across requests.

10. How do we use session and cookie to keep user information across the the application?
1. User Logs In
Server authenticates user.
Stores user info (like user ID or role) in a session.
Generates a session ID.
Sends that session ID in a cookie to the browser.
// In Spring Boot (Controller)
@PostMapping("/login")
public String login(HttpSession session) {
    session.setAttribute("username", "john_doe");
    return "redirect:/home";
}
Browser saves the cookie:
Set-Cookie: JSESSIONID=abc123; Path=/; HttpOnly
2. Subsequent Requests
Browser sends the JSESSIONID cookie automatically with each request.
Server retrieves the session using the session ID.
Retrieves user info from the session.
@GetMapping("/home")
public String home(HttpSession session) {
    String username = (String) session.getAttribute("username");
    // Use it to personalize the response
    return "Welcome " + username;
}
3. Cookie Example (Client-Side Preference)
You can also set cookies for user preferences like theme or language:
@GetMapping("/set-theme")
public ResponseEntity<String> setTheme(HttpServletResponse response) {
    Cookie themeCookie = new Cookie("theme", "dark");
    themeCookie.setMaxAge(7 * 24 * 60 * 60); // 7 days
    response.addCookie(themeCookie);
    return ResponseEntity.ok("Theme set to dark");
}
11. What is the spring security filter?
A Spring Security Filter is part of the filter chain in a Spring Boot application that intercepts HTTP requests before they reach your controllers. It allows Spring Security to:
    Authenticate users (e.g., login, token verification)
    Authorize access to resources (e.g., check roles/permissions)
    Handle security logic like CSRF protection, headers, etc.
12. Explain bearer token and how JWT works.
A Bearer Token is a type of access token that is sent in the Authorization header of an HTTP request. Whoever holds the token can access the resource - no password required, just the token.
How JWT Works:
    User Logs In:
        The client sends login credentials (e.g., username & password). The server authenticates the user and creates a JWT. The JWT is sent back to the client.
    Token Stored on Client:
        The JWT is stored in localStorage, sessionStorage, or a cookie
    Client Makes Authenticated Requests:
        On every request to a protected resource, the client includes the JWT
    Server Verifies JWT:
        The server verifies the signature using the secret key. If valid and not expired, it uses the payload (claims) to identify the user.

14. Compare UserDetailService, AuthenticationProvider, AuthenticationManager, AuthenticationFilter?(把这⼏
个名字看熟悉也⾏)
UserDetailService: Responsible for loading user-specific data (like username, password, roles) during authentication.
AuthenticationProvider: Performs the actual authentication logic, Uses UserDetailsService to retrieve user and validate credentials.
AuthenticationManager: Coordinates the authentication process, Delegates to one or more AuthenticationProvider instances.
AuthenticationFilter: Captures login requests (typically HTTP POST with username & password), Converts credentials into an Authentication object, Sends it to the AuthenticationManager.
| Component               | Role                                                  |
|-------------------------|-------------------------------------------------------|
| `UserDetailsService`    | Loads user from database (by username)               |
| `AuthenticationProvider`| Validates credentials using UserDetailsService       |
| `AuthenticationManager` | Orchestrates the authentication via providers        |
| `AuthenticationFilter`  | Intercepts login request and starts the process      |
15. What is the disadvantage of Session? how to overcome the disadvantage?
    1. Not Scalable: Stored on server; hard to scale with many users.
    Use Redis or switch to stateless JWT.
    2. Sticky Sessions: Needs same server for requests.
    Use shared session storage or stateless auth.
    3. Security Risk: Session ID hijacking.
    Use HTTPS, HttpOnly/Secure cookies, regenerate session IDs.
    4. Not RESTful: Violates stateless API design.
    Use JWT for REST APIs.
    5. Resource Usage: Sessions consume memory until cleaned.
    Set session timeout & cleanup strategy.
