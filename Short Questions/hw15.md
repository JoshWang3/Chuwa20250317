3. Compare let vs var , explain variable hosting with your own code examples.
Use let to avoid issues with hoisting and to maintain block-level scoping.
Use var if you need function-level scoping, but it's generally advised to avoid it in modern JavaScript due to its quirks.
```javascript
console.log(a);  // Outputs: undefined (due to var hoisting)
var a = 5;

console.log(b);  // ReferenceError: Cannot access 'b' before initialization
let b = 10;

```
4. Explain closure with code example
A closure in JavaScript refers to a function that "remembers" its lexical scope, even when the function is executed outside that scope. This means that a closure allows a function to access variables from its outer (enclosing) function even after the outer function has finished executing.
```javascript
function outer() {
  let outerVar = "I am from the outer function";

  function inner() {
    console.log(outerVar); // inner function has access to outerVar from the outer function
  }

  return inner;
}

const closureExample = outer(); // The outer function is executed, and inner function is returned
closureExample();  // Outputs: "I am from the outer function"

```
5. Explain Callback Hell with code example
   Callback hell (also known as "Pyramid of Doom") refers to a situation in asynchronous programming where multiple nested callbacks make the code difficult to read, maintain, and debug. This typically happens when you have a series of asynchronous operations (such as reading files, making network requests, etc.) that depend on the result of the previous one, leading to deeply nested callbacks.
```javascript
function firstTask(callback) {
  setTimeout(() => {
    console.log('First task completed');
    callback();
  }, 1000);
}

function secondTask(callback) {
  setTimeout(() => {
    console.log('Second task completed');
    callback();
  }, 1000);
}

function thirdTask(callback) {
  setTimeout(() => {
    console.log('Third task completed');
    callback();
  }, 1000);
}

function fourthTask(callback) {
  setTimeout(() => {
    console.log('Fourth task completed');
    callback();
  }, 1000);
}

// Callback hell: nested callbacks for sequential tasks
firstTask(() => {
  secondTask(() => {
    thirdTask(() => {
      fourthTask(() => {
        console.log('All tasks completed');
      });
    });
  });
});

```
6. Explain Promise , Async , Await with code examples.
   In JavaScript, Promises, Async, and Await are features that allow for better handling of asynchronous code, helping to avoid issues like callback hell and providing cleaner and more readable solutions.
```javascript
function fetchData() {
  return new Promise((resolve, reject) => {
    const success = true; // Simulate success/failure condition
    setTimeout(() => {
      if (success) {
        resolve("Data fetched successfully!");
      } else {
        reject("Error fetching data.");
      }
    }, 1000);
  });
}

fetchData()
  .then((data) => {
    console.log(data);  // Outputs: Data fetched successfully!
  })
  .catch((error) => {
    console.log(error); // In case of error
  })
  .finally(() => {
    console.log("Fetch attempt finished.");
  });

```

9. Explain how Javascript implement asynchronous non-blocking feature
1. Particularly: Event Loop, Macrotask, and Microtask with code samples.
   Please submit code, answers, and screenshots to your GitHub branch.
JavaScript implements asynchronous, non-blocking behavior through the Event Loop, Macrotasks, and Microtasks. These concepts allow JavaScript to handle multiple operations concurrently, without blocking the main thread, which is crucial for smooth user experiences, especially in environments like browsers.

Key Concepts:
Event Loop: The mechanism that handles the execution of code, events, and messages in JavaScript. It continuously checks if the call stack is empty and if there are tasks in the task queue (macrotasks and microtasks) to be executed.
Macrotask: Represents tasks that are typically scheduled by JavaScript APIs (like setTimeout, setInterval, I/O operations, etc.). Macrotasks are executed in a queue that is processed one at a time by the event loop.
Microtask: Represents tasks that are often scheduled by promises (Promise.then(), Promise.catch(), etc.). Microtasks have higher priority than macrotasks and are executed after the current task in the call stack finishes and before the next macrotask is processed.
```javascript
console.log("Start");

// Macrotask: setTimeout
setTimeout(() => {
  console.log("Macrotask 1");
}, 0);

// Microtask: Promise resolution
Promise.resolve().then(() => {
  console.log("Microtask 1");
});

// Another Macrotask: setTimeout
setTimeout(() => {
  console.log("Macrotask 2");
}, 0);

// Another Microtask: Promise resolution
Promise.resolve().then(() => {
  console.log("Microtask 2");
});

console.log("End");

```
