# Explain and compare following concepts, provide specific examples when doing comparison:
## Testing related:
### Unit Testing
- **What:** Tests individual components (functions, methods, classes) in isolation.
- **Goal:** Ensure each unit of code works as expected.
- **Example:** Test a function that calculates tax in a billing system.
- **Tools:** JUnit (Java)

### Functional Testing
- **What:** Tests a piece of software against business requirements.
- **Goal:** Validate if the system behaves as expected (from the user’s perspective).
- **Example:** Testing login functionality: user enters correct username/password → lands on the dashboard.
- **Tools:** Postman

### Integration Testing
- **What:** Tests combined parts/modules of the application to ensure they work together.
- **Goal:** Catch issues in module interaction.
- **Example:** A shopping cart system where Add to Cart module interacts with Inventory and Pricing modules.
- **Tools:** JUnit + Mockito, Postman, REST Assured.

### Regression Testing
- **What:** Re-run previous test cases to ensure new changes didn’t break existing functionality.
- **Goal:** Verify software stability after updates.
- **Example:** After fixing a login bug, you retest login, user profile, and dashboard features.
- **Tools:** Selenium, QTP, Jenkins (CI/CD regression suites).

### Smoke Testing
- **What:** Basic checks to ensure critical features work in a new build.
- **Goal:** Decide whether a build is stable enough for deeper testing.
- **Example:** Run a quick test to see if login, navigation bar, and product search work right after a new deployment.
- **Tools:** Automated scripts or manual checklist.

### Performance Testing
- **What:** Measures system’s speed, scalability, and stability under a specific workload.
- **Goal:** Assess how fast the system responds under normal conditions.
- **Example:** Check how fast a search returns results with 1,000 users online.
- **Tools:** JMeter, Gatling, LoadRunner.

### Stress Testing
- **What:** Tests the system under extreme conditions to see its breaking point.
- **Goal:** Understand how much load your system can handle and how it recovers from failure.
- **Example:** Simulate 10,000 users placing orders at once during Black Friday.
- **Tools:** Apache JMeter, BlazeMeter.

### A/B Testing
- **What:** Compares two versions (A and B) of a feature with real users to see which performs better.
- **Goal:** Optimize user experience or conversion rate.
- **Example:** Show 50% of users a blue “Buy Now” button and 50% a green one. Measure which version leads to more sales.
- **Tools:** Google Optimize, Optimizely, VWO.

### End-to-End Testing
- **What:** Simulates real user scenarios across the entire application.
- **Goal:** Validate the complete workflow from start to finish.
- **Example:** User signs up → browses products → places order → receives confirmation email.
- **Tools:** Cypress, Selenium, Playwright.

### User Acceptance Testing
- **What:** Final round of testing by end users or clients before software goes live.
- **Goal:** Confirm that the system meets business needs.
- **Example:** Client tests an employee portal to verify that leave request, approval, and notification workflows match HR policy.
- **Tools:** UAT scripts, test management tools like TestRail, or even Excel.

## Environment related:
### Development
- **What:** Where developers write and test code during active development.
- **Goal:** Rapid iteration and testing of new features or bug fixes.
- **Example:** A developer builds a “wishlist” feature in an e-commerce app. They test it locally or on a dev server.
- **Tools:** Local IDE, Docker containers, Git branches (dev, feature/wishlist), VSCode Debugger.

### QA (Quality Assurance)
- **What:** Where dedicated QA testers verify that new changes meet requirements.
- **Goal:** Catch bugs before releasing to users.
- **Example:** QA tests the “wishlist” feature to confirm it saves correctly, works with login, and doesn’t affect the shopping cart.
- **Tools:** Test automation suites (Selenium, Cypress), CI/CD pipelines (Jenkins, GitLab), test case managers.

### Pre-prod/Staging
- **What:** A production-like environment for final validation before release.
- **Goal:** Final round of testing—especially integration and user acceptance.
- **Example:** Product manager tests the full checkout flow using staging data, verifying behavior across multiple systems (payment gateway, email, inventory).
- **Tools:** Real backend services, mirrors production configurations, feature flags.

### Production
- **What:** The live system accessed by real users.
- **Goal:** Deliver reliable, high-performance service to end-users.
- **Example:** A customer logs into your e-commerce site, browses products, and completes a purchase.
- **Tools:** Real databases, load balancers, logging tools (Datadog, ELK), monitoring (New Relic, Prometheus), alerting (PagerDuty).
