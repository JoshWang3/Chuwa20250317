2. Explain monolithic architecture, service oriented architecture and Micro service architecture.
   Monolithic Architecture: A single unified application where all components (UI, business logic, data access) are tightly coupled and run as one.
   Service-Oriented Architecture: Application is broken down into reusable services, which can be shared across systems. Often uses Enterprise Service Bus (ESB) to communicate.
   Microservices Architecture: Application is split into independent, loosely coupled services, each owning its own data and logic, often communicating via REST/gRPC.
3. Document the microservice architeture and core components
   1.API Gateway
   Acts as a single entry point for clients. Handles request routing, load balancing, authentication, and more.
   Example: Spring Cloud Gateway, Kong, Nginx
   2.Service Registry & Discovery
   Keeps track of all active services and their instances. Enables dynamic discovery and load balancing.
   Example: Eureka, Consul, Zookeeper
   3.Config Server / Centralized Configuration
   Stores configuration settings for all services centrally. Supports dynamic updates without redeploying.
   Example: Spring Cloud Config, Consul KV
   4.Inter-Service Communication
   Services communicate via: Synchronous (REST/gRPC), Asynchronous (Messaging/Events).
   Example: RabbitMQ, Kafka, gRPC, REST
   5.Database per Service
   Each microservice manages its own database/schema. Promotes loose coupling and data ownership.
   Supports: SQL, NoSQL, or Polyglot persistence
   6.Circuit Breaker / Resilience
   Prevents cascading failures. Fallback logic and retries when services fail.
   Example: Resilience4j, Hystrix (deprecated)
   7.Observability
   Includes logging, monitoring, and tracing.
   Tools: Logging: ELK Stack, Fluentd; Monitoring: Prometheus + Grafana; Tracing: Zipkin, Jaeger, Spring Cloud Sleuth
   8.Security
   API Gateway enforces authentication & authorization. Services often use OAuth2 / JWT for identity.
   Example: Keycloak, Auth0, Spring Security
   9.CI/CD Pipeline
   Automates testing, building, and deployment of each service independently.
   Tools: Jenkins, GitHub Actions, ArgoCD, Spinnaker
   10.Containerization & Orchestration
   Services are deployed as containers. Orchestration platforms manage scaling, networking, and recovery.
   Tools: Docker, Kubernetes
4. Explain Resilience patterns? Explain circuit breaker with Spring Cloud Hystrix code example.
   Resilience patterns are software design patterns that help systems maintain functionality in the face of failure. These patterns are especially important in distributed systems (e.g., microservices) where failures in one service can cascade and affect others.

5. Explain load balancing algorithms.
   Load balancing algorithms determine how incoming traffic is distributed across multiple servers or resources to ensure high availability, reliability, and optimal performance.
   Round Robin, Weighted Round Robin, IP Hash, Least Connections, Least Response Time, Resource-Based / Load-Based
6. Explain API Gateway.
   An API Gateway is a single entry point for all client requests in a microservices system. It acts as a reverse proxy that routes requests to the appropriate backend services, handles common cross-cutting concerns, and improves manageability.
7. Explain service discovery and service registry
   Explain service discovery and service registry
   Service Discovery: Service Discovery is the process of automatically locating services in a distributed system. Since microservices often run on dynamic IPs (containers, autoscaling, etc.), hardcoding service addresses is not reliable.
   Service Registry: A Service Registry is a central database where all services register themselves and lookup other services.
